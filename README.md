# LEN-RP-int-helper
# RP Int 预填助手 — 安装与使用（v1.7.0）

针对资源计划（RP）录入页做的 Chrome 扩展。
在侧边栏里选人 → 一键把该人的信息填进表单 → 你核对后手动保存。

---

## 一、安装

1. Chrome 地址栏打开 `chrome://extensions/`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」
4. 选择本文件夹（`rp-autofill`，里面要有 `manifest.json`）
5. 更新版本后，回到 `chrome://extensions/` 点插件卡片上的 **刷新**（🔄）按钮重新加载

> 需要 Chrome **114 或更高版本**（右侧边栏 API 要求）。
>
> 用到 `debugger` 权限（供「真人动作」的可信输入通道使用）。
> 它**不会**读取你的页面内容，只是在你要执行时短暂接管输入设备模拟点击，
> 动作结束立即释放。安装时若提示该权限，允许即可。

---

## 二、第一次使用（必做，只做一次）

1. 点浏览器工具栏的插件图标 → 打开右侧边栏
2. 在 **⓪ 目标页面** 里把 **RP 录入页的地址**粘进去，点 **「打开 URL 到本页」**（或「打开 URL 到新页签」）。
   地址会自动记住，以后打开侧边栏就带出来，不用再填。

   > 前提是已经在同一个 Chrome 里**登录**了目标系统。

3. **等页面完全加载完**（表单字段都显示出来），回到侧边栏
4. 点 **① 探测表单字段 → 「探测字段」**

   这一步是必须的：插件靠它拿到 RP 实体的真实字段清单
   （schema 名、类型、是否必填、选项集有哪些值）。探测成功后字段清单会缓存，以后不用重复探测。

5. 展开「查看字段清单」确认能识别出字段。

## 三、界面总览

侧边栏自上而下六个区块（编号沿用历史，**没有 ③**）：

| 区块 | 作用 |
|------|------|
| **⓪ 目标页面** | 第一次把 RP 录入页地址填进来；一键打开到本页 / 新页签 |
| **① 探测表单字段** | 拉取/扫描页面字段清单；探测不到时的排查入口 |
| **② 选择人员** | 选人（单选）；维护 Name / ItCode；批量导入人员 |
| **④ 真人动作：触发顺序** | 编辑要执行的步骤清单（字段名 / 值 / 类型）；批量导入月份数值 |
| **⑤ 执行预填** | 一键「执行预填」；清空我填的；列出下拉 |
| **⑥ 步骤回执**（底部） | 每一步的执行明细，默认折叠 |

### ⓪ 目标页面

- **URL 输入框**：第一次使用时把 RP 录入页的完整地址粘进来（`http://` 或 `https://` 开头）。
  改完自动记住，下次打开侧边栏会自动填回来。
- **「打开 URL 到本页」**：把**当前标签页**导航到这个地址，然后就能直接开始探测。
- **「打开 URL 到新页签」**：新开一个标签页打开，保留你当前的页面。
- 地址不合法（没带 http/https）时会直接提示，不会瞎跳。

## 四、日常使用

1. 打开 RP 录入页（空白的「新建」表单；可用 ⓪ 一键打开）
2. 侧边栏 **② 选择人员**：点某一行的 **单选按钮** 选中该人（选中后该人的 ItCode 会自动喂给
   ④ 里的 Resource 步骤）
3. **④ 真人动作：触发顺序** 一般不用动（出厂已配好）
4. 点 **⑤ 执行预填 → 「执行预填」**

   这一个按钮是**合并**动作：先用真人动作把触发字段选上（触发表单联动展开），
   再自动把该人的其余字段填进去。顺序固定、全程走可信输入。

5. 回录入页**核对**，确认无误后**手动点保存**

> 插件**不会**自动保存。这是刻意设计：财务数据填错直接提交代价太大，
> 永远留一道人工确认。填错了点 **「清空我填的」**。

执行完可以在底部 **⑥ 步骤回执** 看每一步做了什么（见第八节）。

## 五、④ 真人动作：触发顺序

RP 表单是**联动**的：填完 `Source Type` / `Type` 之后，表单才展开人员信息字段区。
所以「先选触发字段、再填人员字段」这个顺序不能变。这一块就是那个**执行清单**。

### 出厂清单（17 步，自上而下依次执行）

| # | 字段名 | 值 | 类型 |
|---|--------|----|----|
| 1 | Source Type | Internal | 下拉 |
| 2 | Type | Project | 下拉 |
| 3 | Project | LI2500347 | 搜索 |
| 4 | **Resource** | *（留空）* | 搜索 |
| 5 | FYear(FYyy) | FY26 | 文本 |
| 6–17 | Apr / May / Jun / Jul / Aug / Sep / Oct / Nov / Dec / Jan / Feb / Mar | *（留空）* | 数字 |

- 每行都可改 **字段名 / 要选择的值 / 类型**（下拉、搜索、文本、数字），改完自动保存。
- **第 4 步 Resource 的值留空即可** —— 留空时自动取 **② 选中人员的 ItCode**。
  选了谁，Resource 就是谁的 ItCode，不用手填。
- **值留空的步骤会自动跳过**，并继续填下一个有值的字段（12 个月空着不影响别的字段）。
- **加一步**：加自定义步骤；**去掉重复**：同名字段出现多次时只保留最后一次
  （否则同一个字段会被录入两遍）。
- 类型说明：**下拉**（选项集）/ **搜索**（Lookup，如 Project/Resource，输入关键字后点第一条匹配）/
  **文本**（可信键盘输入）/ **数字**（可填小数）/ **整数**（非负整数）。
  12 个月出厂用的是「数字」。

## 六、批量导入月份数值

12 个月的数值可以从 Excel 直接粘贴，不用一格一格敲。

**④ 真人动作：触发顺序** 下方 → 展开 **「批量导入月份数值（从 Excel 复制粘贴）」**，
粘贴**两行**：

```
26-Oct	26-Nov	26-Dec	27-Jan
1	1	1	1
```

- **第一行是月份表头，第二行是对应的数值**。
- 月份按 **英文 Jan…Dec** 识别，支持缩写/全称/带年份前缀：`26-Oct`、`Oct`、`October`、`Dec-26` 都行。
- **列的顺序随意** —— 按月份**对号入座**，不是按位置。`27-Jan 26-Oct / 5 3` 会得到 `Jan=5, Oct=3`。
- **只填其中几个月也行**，其余月份保持不动；某个数值留空则清空该月。
- 也支持**纵向**粘贴（每行 `月份 数值`），会自动判别。

点 **「导入月份数值」**，回执会列出「已导入 N 个月份 Oct=1、Nov=1…」；
表头里出现了顺序中不存在的月份时，会提示「顺序里没有这些月份」。

## 七、真人动作：可信输入

### 为什么要走这条路

页面脚本合成的鼠标/键盘事件，其 `isTrusted = false`。目标系统（Fluent UI）**有充分的理由忽略
这类事件** —— 浏览器就是靠这个标志区分「真人操作」和「脚本操作」的。表现就是：
下拉看起来开了、值也写进去了，但业务联动就是不触发，新字段区不展开。

所以触发字段改由后台通过 **CDP 的 `Input.dispatchMouseEvent` / `dispatchKeyEvent`**
派发**可信事件**。对页面来说，这和你本人拿鼠标操作完全等价，联动必定按真实用户的路径走。

### 怎么用

点 **⑤ 执行预填 → 「执行预填」**（默认就会先做真人动作，不需要额外勾选）。
执行时回执里每一步都列出来，卡在哪一步一目了然：

```
① 定位字段   Source Type  button combobox (312,486)
② 点开下拉   (312,486)
③ 读取选项   2 项：External / Internal
④ 点中选项   Internal (312,524)
⑤ 校验       Internal ✓   字段 5 → 11
```

触发字段没选上时**会停下来**，不会把值写到还没展开的表单上。

### 真人动作做了什么（按顺序）

| 步骤 | 动作 | 为什么 |
|------|------|--------|
| ① | 找到字段控件并滚到视野内 | 看不见就没法点 |
| ② | 鼠标**先移过去**，再按下、释放 | 真人的顺序；直接 click 位置不对会点空 |
| ③ | 异步等下拉渲染，读全部选项 | 同步等待会阻塞页面，下拉反而渲染不出来 |
| ④ | 鼠标移到选项上，按下、释放 | 同上 |
| ④' | 找不到选项时改**键盘**：连按 ↓ 走到目标再回车 | 某些下拉只用键盘走位 |
| ⑤ | 回读控件显示值 + 比对字段数 | 值对不对、表单有没有展开，都要如实报 |

搜索字段（Project / Resource）走的是「输入关键字 → 读最新弹出的结果列表 → 点第一条匹配」，
并且**只从最新弹出的列表里取**，避免把上一次下拉的残留选项当成结果。

### 两个你需要知道的现象

- **页面顶部会短暂出现「正在受自动测试软件控制」提示条** —— 这是 Chrome 对
  调试通道的强制提示，动作结束就消失，不影响页面，也不会改任何数据。
- **该页面不能同时开着 DevTools**（会抢占调试通道）。
  如果开着，会报「可信输入通道不可用」并自动退回旧的合成事件方式重试。

## 八、⑥ 步骤回执（底部面板）

侧边栏最底部是 **⑥ 步骤回执**，用来查看每一次执行到底做了什么。

- 默认是**收起**的，只显示一行 **overview** 汇总：

  ```
  [有失败] 共 17 步 · 成功 5 · 跳过 12 · 失败 0
  失败步骤：MD Confirm、Start Date
  ```

  其中「跳过」= 值为空、按设计不执行的步骤（如没填的月份），**不是失败**。

- 点 **「▸ 展开步骤回执」** 展开看**每一步的明细**（定位/点开/读选项/点中/校验 + 回读值），
  再点一次收起。定位问题时先看这里。

## 九、② 选择人员

- 每行左侧的 **单选按钮** 用来选中当前要预填的人。
- 行内 **Name / ItCode 两列宽度相同，均可直接编辑**，改完自动保存。
- **新建** 加一个人；**删** 删掉该行。
- 首次安装会自带一条 **张三 / zhangs1** 示例，照着改就行。
- 选中的这个人的 **ItCode 会自动同步到 ④ 的 Resource 步骤**；其余字段值在 ⑤ 的填充阶段被使用。

### 批量导入人员

**② 选择人员 → 批量导入（从 Excel 复制粘贴）**，从 Excel 复制**两列**直接粘贴：

| 姓名 | ItCode |
|------|--------|
| 张三 | zhangs1 |

- 第一行是表头，固定两列：**姓名** 与 **ItCode**。
- **姓名** 用来显示和去重（同名会合并覆盖，不产生重复人员）。
- **ItCode** 会填进 Resource 字段；写成 `ItCode` / `It Code` / `itcode` / `Resource` 都能认。
- 需要额外字段值（如 `yearmonth`、`md`）时，再往后加列，列名填 schema 字段名即可
  （探测清单里能看到），值随便写，`2026/1/5`、`2026-01`、`1,234.5`、`50%`、
  Excel 日期序列号都会自动归一。

**导出当前为 TSV** 可做备份。

## 十、默认值怎么设

- **设置页**：侧边栏底部「设置页」链接，或扩展详情页的「扩展程序选项」

规则：

- 默认值只在**人员没填该字段**时生效
- 同名字段**以人员值为准**，默认值让位

例：把 `yearmonth` 默认设成 `2026-10`，以后新建人员只要不填这项，就会自动带上。

## 十一、探测不到字段怎么办

目标页面结构比较特殊：主文档 + 十几个 iframe。插件会逐个 frame 尝试，
失败时分两类，侧边栏会分别说明。

### 情况 A：显示「脚本未注入到任何 frame」

侧边栏会**列出每个 frame 的 URL** 并标注「同域 / 跨域」，据此判断：

| 提示 | 原因 | 处理 |
|------|------|------|
| 提示未刷新 | 扩展更新后，页面还是旧的脚本 | 在页面按 **F5**，或点侧边栏的 **「强制注入脚本」** |
| 有「跨域?」标记 | 表单放在了别的域名下，插件无权限 | 见下面「补充权限」 |
| frame URL 是 `about:blank` | 空白 iframe | 已通过 `match_about_blank` 覆盖，点强制注入即可 |

### 情况 B：显示「脚本已注入，但没拿到字段」

| 提示 | 原因 | 处理 |
|------|------|------|
| 元数据 403 | 你的账号没读实体元数据的权限 | 不影响使用，已自动降级为页面扫描 |
| 各 frame 控件数都是 0 | 表单还没渲染完 | 等字段都显示出来再点探测 |
| 控件数不为 0 但没归类成字段 | 定位策略跟这个版本不匹配 | 点 **「排查：导出页面结构」**，把结果发我 |

### 补充权限（仅当出现「跨域?」时需要）

`chrome://extensions/` → 找到插件 → **详细信息** → **网站访问权限**，
把显示跨域的那个域名也勾上。

### 诊断导出

点 **「排查：导出页面结构」→「复制诊断结果」**，把内容发我。包含：主文档和每个 iframe
的控件数、命中的 CSS class 模式、前 8 个控件的 HTML 片段。有它我能一次改对，比反复试快得多。

## 十二、字段填不进去怎么办

侧边栏填充后会给逐字段结果（成功 / 失败 + 原因）。常见情况：

| 现象 | 原因 | 处理 |
|------|------|------|
| 「页面未找到该字段容器」 | 该字段在当前表单页没有显示（折叠分区、只读字段） | 在页面上把该分区展开，让字段可见，再填一次 |
| 值填进去了但页面没反应 | 表单是 React 渲染的 | 插件已用原生 setter + 完整事件链处理；若仍无效，请反馈该字段名 |
| Lookup（人员/项目引用）提示「需手动点选」 | 引用字段要等异步搜索结果 | 在下拉里手动点一下正确记录，或勾选「搜索字段自动点选第一条匹配结果」 |
| 下拉已展开但未找到选项 | 填的值不在选项集里 | 在探测清单里看该字段的选项值，用 label 文本而不是内部 value |
| 值填进去了但**表单不展开** | 触发字段没选上 | 看底部 **⑥ 步骤回执** 定位是哪一步失败；在页面上手点一次下拉兜底 |

## 十三、这个插件怎么工作的（技术说明）

```
侧边栏 (sidepanel.js)
   │
   ├─ chrome.tabs.sendMessage ──► content script (content.js)
   │      │  ├─ RP_PROBE → lib/probe.js 拉 Web API 元数据
   │      │  │            → lib/filler.js 扫 DOM（降级路径）
   │      │  └─ RP_FILL  → lib/probe.js buildPlan 合成填充计划
   │      │              → lib/filler.js fillField 逐字段写入（合成事件）
   │      │
   │      └─ RP_HUMAN_*  → 提供坐标/选项/回读状态（供可信输入用）
   │
   └─ RP_HUMAN_PICK ────► background.js
          CDP attach → Input.dispatchMouseEvent / dispatchKeyEvent
          （可信输入，等价于真人操作；编排见 lib/human.js）
   ▼
表单控件
```

关键实现点：

1. **React 受控组件**：`el.value = x` 不会更新框架状态，保存时拿到的还是旧值。
   所以走原生 setter，再依次派发 `input` → `change` → `keyup` → `blur`。
2. **同值也要重写**：写入前先清空再写，绕开 React「值未变就跳过 onChange」的优化。
3. **控件类型分流**：文本 / 数字 / 日期 / 布尔 / 选项集 / Lookup，各有各的写入方式。
4. **定位策略**：自底向上冒泡找「像字段容器」的祖先，再按 `data-field-name` → id/name 子串 →
   label 文本三级匹配，跨版本不易失效。
5. **iframe 兼容**：`all_frames` + `match_about_blank` 全注入；填充只发 top frame
   再由 content script 自行遍历 iframe —— **否则会重复填**。
6. **权限降级**：Web API 元数据接口按版本依次尝试，全部失败则降级为 DOM 扫描。
7. **零依赖**：MV3 + 原生 JS，无框架无构建，`lib/` 下文件可单独载入做单测。
8. **可信输入**：触发字段由 background 通过 CDP 派发**可信**鼠标/键盘事件，
   编排在 `lib/human.js`（纯逻辑、可单测），详见第七节。
9. **月份导入**：表头识别与版式判别在 `lib/util.js` 的 `monthKey` / `parseMonthImport`
   （纯函数，可单测）。

### 实测确认的页面事实（来自真实诊断）

- 新建空白记录表单：标题 `Resource Plan: Information: New Resource Plan`，URL 无 `id`
- **字段在主文档**，不在业务 iframe 里
- 表单用 **Fluent UI**，字段容器 class 是哈希名（不可依赖），只能靠 `aria-label` 定位：
  - 下拉：`<button type="button" role="combobox" aria-label="Source Type">`
  - 文本：id 里嵌着 schema 名（如 `...-<schema>.fieldControl-text-input-component`）
- 表单是**联动**的：填完 Source Type / Type 后才展开人员信息字段区
- Web API 元数据接口对本账号不可读（探测走 DOM 降级路径）

```

├── lib/
│   ├── util.js            值归一（日期/数字/TSV）+ 月份识别/导入 + 回执汇总 —— 纯函数
```
